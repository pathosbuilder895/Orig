# Pre-registration: rule D against AI-written papers (20-paper screen)

| | |
|---|---|
| **Tool** | Claude Code; `validation/scholarly/ai_mirror.py` |
| **Date** | 2026-11-18 (written and committed before any AI paper exists and before `locked_test` is opened for this study) |
| **Question** | When an AI chat tool writes a paper with the same title, for the same journal, as one of an author's own held-out papers, does rule D flag it against that author's past papers? |
| **Decision it informs** | Whether rule D is clearly short of a 95% catch rate on AI-written papers, or whether 95% is not ruled out and a larger (about 130-paper) study is worth pre-registering. Nothing in the product changes either way. |

**Study id:** `scholarly-ai-mirror-2026-11-16`

**Nothing about the targets, the prompts, the cleaning, rule D, its thresholds, the seeds, the
trial design or the decision rule will change after this file is committed, and the results
will be reported exactly as they come out.** The design is
`docs/superpowers/specs/2026-11-16-rule-d-ai-mirror-design.md`; this file fixes its values.
These are published humanities papers, not student writing, and 20 papers is a screen: it can
rule 95% out, it cannot show it.

## Generating the papers

* **Route:** all 20 papers are generated by Andrew Clark in the consumer chat apps (claude.ai,
  ChatGPT, Gemini), each in a new chat, with whatever model the app uses by default that day.
  The model name the app shows is recorded per paper. No paper is written by Claude Code.
* **Prompt, identical for every tool** (`prompts_humanities.md`):
  > Write an original scholarly journal article of about 1,600 words titled "{title}",
  > suitable for publication in {venue}. Write continuous academic prose in paragraphs. Do
  > not use headings, bullet points, numbered lists, tables, footnotes or a reference list.
* **One continuation, only when the cleaned first reply is under 1,300 words**, sent once in
  the same chat and saved to its own file:
  > Please continue the article from where it stopped, in the same style, for about 600
  > more words.
* No other re-prompting, regenerating or editing. Only published titles and journal names
  leave the machine; no student writing does.

## Cleaning (fixed in code at the commit of this file)

Each reply and its continuation are cleaned separately, then joined:

1. Cut from the first line that, ignoring `#`, bold or italic marks, a section number and a
   trailing colon, reads: references, reference list, bibliography, select bibliography,
   works cited, literature cited, sources, notes, endnotes or further reading.
2. Drop markdown headings, a line that only repeats the title, emphasis marks and list markers.
3. Drop a first paragraph that opens with a stock assistant phrase (certainly, sure, of
   course, absolutely, here is, here's, below is, I've written, I have written) or ends with
   a colon, and trailing paragraphs offering further help (let me know, would you like, if
   you'd like, if you would like, I hope this, feel free, I can also, happy to).
4. Apply the corpus's own inline cleaner (citations, footnote markers, URLs).
5. Drop paragraphs under 12 words, as the corpus cleaner does for papers, then look again for
   trailing help offers that a short last line (such as "---") had hidden.
6. Cut a trailing block of reference entries: paragraphs that start like an entry (a surname
   then a comma), contain a year (1500-2099, in parentheses or followed by a period) and a
   bibliographic marker (pp., ed., eds., Vol., doi, Press, Journal, University, Review),
   judged on the text before step 4.

Paragraphs removed by steps 1, 3 and 6, and help offers found again in step 5, are counted in
`validation/scholarly/ai_mirror/manifest_humanities.json` (`cut_heading_paragraphs`,
`cut_wrapper_paragraphs`, `cut_reference_paragraphs`), and any non-zero count is read before
the papers are committed. `intake` refuses to record a reply while an unrecorded continuation
file exists. Everything after a reference heading (entries, and any sign-off after them) is
counted once, under `cut_heading_paragraphs`, as a raw count of blank-line-separated blocks.
Paragraphs under 12 words are dropped without a count, as the corpus cleaner does for papers.

## Scoring

* Rule D exactly as pre-registered on 2026-11-12 (`scholarly-rule-d-2026-11-12`), with the
  committed thresholds, which are also pinned as constants in `ai_mirror.py`:

| 300 vs 300 | 1200 vs 1200 | 1200 past vs 300 new |
|---|---|---|
| −0.529301 | −1.244517 | −0.919008 |

* Each AI paper is scored in the seed-7 trial of each configuration, cut at a seeded
  paragraph start to that configuration's new-paper length, against the claimed author's 4
  past papers, compared with every other author in the trial set. Flagged means D is
  strictly above the threshold.
* A paper under 1,200 cleaned words after its one continuation enters only the two 300-word
  configurations and is reported as missing from 1200 vs 1200.

## What is reported

For each configuration:

* caught out of n, with a Wilson 95% interval;
* the outcome below;
* the per-tool counts, which are descriptive only (about 7 per tool);
* beside them, how many of the same authors' own new papers were flagged in the same trials.

Also reported:

* a reproduction of every published cell of the 2026-11-12 locked result;
* any missing authors;
* any protocol notes.

**Primary** is 1200 vs 1200. **Secondary** is 1200 past vs 300 new, the short-paper case where
rule D was weakest. 300 vs 300 is reported only.

## Decision rule (per configuration)

* **Below 95%** when the top of the Wilson 95% interval is under 95%. With 20 papers that is
  17 or fewer caught.
* **95% not ruled out** otherwise (18 or more of 20). The next step is a separately
  pre-registered study of about 130 AI papers before any 95% claim.
* If fewer than 20 papers enter a configuration, the same rule applies to the actual n.

## Opening procedure

1. Commit and push this file before any AI paper is generated.
2. Generate, record (`intake`) and commit the 20 papers; push.
3. In one Claude Code cloud session on this branch (Linux, `poppler-utils`):
   * restore the humanities corpus, cleaning each paper with the cleaner version it was
     recorded with;
   * run `--verify`;
   * run `python -m validation.scholarly.ai_mirror check-env`.
4. The gate passes only if all three recomputed calibration thresholds equal the committed
   ones to 6 decimals.
   * **If it fails:** stop, commit the environment file, and report to Andrew. `locked_test`
     is not opened, and the AI papers stay committed and unused.
   * **If it passes:** commit and push the environment file.
5. Run `python -m validation.scholarly.ai_mirror locked --study scholarly-ai-mirror-2026-11-16`
   once.
   * It refuses unless every guard passes, and it appends exactly one line to
     `LOCKED_OPENINGS.tsv`.
   * Results go to `validation/scholarly/ai_mirror_humanities_locked_test_<date>.json`.
   * If a run crashes after the opening is logged, it is not re-run without the owner's
     approval, and the crash is reported.
