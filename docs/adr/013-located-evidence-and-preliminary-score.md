# ADR-013: Located evidence passages and an optional preliminary score (staff only)

**Status:** Accepted (#314, merged); all-measurements extension (items 9–14, #318, merged); teacher side-by-side view (items 15–21, #319, merged); comparison measurements not compared (`fix/comparison-placeholders`, awaiting Andrew)
**Date:** 2026-10-24
**Deciders:** Andrew
**Relates to:** `docs/NORTH_STAR.md`; ADR-012 rows "Evidence quotes" and "My Work highlights" (this ADR supersedes the "no text positions exist" reason for staff views only); ADR-011 claim-table rules.

## Context

Andrew, 2026-10-24: "our greatest strength is to not be a black box. We also need preliminary optional scores according to our math". ADR-012 removed quotes because a score response carried no text positions. This ADR adds positions for the features where Original's own count can be reproduced exactly, and a preliminary score that is nothing more than the existing math restated.

## Decision

1. **New module `original/evidence.py`.** It rebuilds the engine's `preprocess()` and `TextDoc` strings with a character map back to the stored text, and refuses (fails closed) if the rebuilt strings differ from the engine's own. For each feature it re-counts using the extractor's exact rule and refuses if its count differs from the extractor's. Only then does it return quotes, and each quote is `text[start:end]` of the stored text, with its offsets.
2. **Ordering is the engine's**: `interference.destructive_features` (|delta| x tier weight, top 5). No new ranking. Up to 3 sentences from the new paper and 3 from past papers (round-robin across papers, document order), deterministic.
3. **Locatable features (23):** `mean_sentence_length`, `sentence_length_variance` (shown as the shortest/longest sentences), `passive_voice_ratio` (approximate pattern, max one per sentence, as the engine), `modal_verb_ratio`, `discourse_marker_density`, `additive_ratio`, `adversative_ratio`, `causal_ratio`, `temporal_ratio` (the four marker ratios count the first use of each marker, as the engine), `transition_density`, `hedging_density`, `assertion_density`, `claim_density`, `question_ratio`, `first_person_ratio`, `appeal_to_authority_density`, `comma_rate`, `semicolon_colon_rate`, `parenthetical_rate`, `dash_rate`, `quote_rate`, `contraction_rate`, `sentence_initial_conjunction_rate`. They are locatable because each is a count of specific characters, words or sentences that can be pointed at.
4. **Every other feature is numbers-only** and labelled so: entropy, distributional, embedding, syntactic-parse, error-topology and similar features are properties of the whole text, and pointing at a sentence would invent a reason.
5. **"What Original measured"**: every evidence payload says how many stored words were measured and shows (verbatim) up to five ranges the preprocessor set aside, with a warning below 80%.
6. **Preliminary score**: `score = round(deviation_score, 2)`, band words from `ACTION_THRESHOLDS`, label "Preliminary · unvalidated · not a judgment". Inconclusive (no score) below the readiness minimum (5 counted, 3 effective). None of "AI detection", "cheating" or "authorship verification" in any wording (tested). *Amended 2026-10-30 (Writing State redesign):* the band words are now the "reads-like" set ("Reads like their own writing" ... "Reads very differently from their past work"), kept in one copy on each side (`original/evidence.py:BAND_WORDS`, `demo/original/live.js` `Live.BAND_WORDS`, a test keeps them equal); the payload also carries `habits_outside` / `habits_compared` (the side-by-side summary's own count, always-on), and the only accuracy-shaped field the product has: `band_rate`, gate G9's measured false-alarm rate for the band, present only after a recorded strict-mode pass (`validation/band_rates.json`, written by `python -m validation.calibration_gate --strict --write-band-rates`), plus `band_rate_status` for the staff Calibration section. What may be quoted and when is NORTH_STAR rule 2 (v0.4), which this item follows rather than restates.
7. **Gating**: `EVIDENCE_PASSAGES_ENABLED` and `PRELIMINARY_SCORE_ENABLED`, both default `0`. When off, `POST /students/{id}/score` is byte-identical (fields are `null`; snapshot regenerated only to add the two null keys). When on, they attach only for non-student principals on HTTP requests; `/me/work` (request=None) and student principals never get them. Neither changes `deviation_score`, the recommendation or anything persisted.
8. **Alpha batch** (`scripts/alpha/batch_score_alpha.py`): writes `out/evidence/<id>.md/.html/.json` and `preliminary_score` / `preliminary_band` CSV columns (staff tool, on by default, `--no-evidence` to skip). report.md accuracy numbers, CSV semantics and calibration are unchanged; labels are never read into evidence.

## Extension: every measurement (2026-10-25, branch `feat/evidence-all-features`)

Andrew approved extending the evidence pages from the top 5 to the whole feature vector.

9. **One section per measurement.** `evidence.build_all_features` returns one entry for every code in `constants.ALL_FEATURE_CODES` (`FEATURE_DIM` entries, read from the registry, never hard-coded); `build_evidence(..., all_features=True)` adds it as `all_features` plus `feature_count` and `all_features_ordering`. The batch scorer and the flag-gated staff API field both pass `all_features=True`.
10. **Values.** The 0–1 values are the engine's: in the API, `result.feature_vector`, each contributing `BaselineSample.vector` and `StudentState.baseline_mean`; in the batch, `extract_features` on the same texts, with the past-paper average taken the way `baseline_mean` takes it (`RECENCY_DECAY` weights, newest 1.0; the batch uploads every past paper as `verified`). Plain units come from `features.pipeline.extract_raw_features`, a behaviour-preserving split of `extract_features` (it returns the dict that `extract_features` normalises; scores are unchanged, guarded by the byte-identity snapshots). For the 23 locatable measurements the plain value is the evidence layer's own located count, as before. If the API cannot show every contributing past paper (a sample without stored text), the full list falls back to the recency-weighted mean of the papers it can show. `past_average_matches_top_list` is false, and the pages say so, when the top list's averages differ from the full list's (for example when the score blended in a population prior for a short baseline).
11. **Order (documented in every page).** Descending `|this paper − past-paper average| × TIER_WEIGHTS[tier]`, the same size measure `_decompose` uses for `destructive_features`, applied to every measurement; ties (including every measurement that does not differ) keep `ALL_FEATURE_CODES` order. The engine's top list additionally requires |z| > 1, so a measurement can rank high in the full list and still be absent from the top list; pages say so, and mark top-list entries with ★. The top-5 "biggest differences" summary stays first, in the engine's order.
12. **Kinds.** `located` (the 23 locatable measurements, with up to 3 verbatim, offset-checked sentences per side in two columns, failing closed exactly as before), `whole_text` ("Whole-text measurement, no single sentence to point to."), `off` (tiers 17 and 18 while in `DISABLED_FEATURE_GROUPS`: every paper gets the fixed middle value) and `not_compared` (the 7 comparison codes, `features/baseline_scope.NOT_COMPUTED_FOR_BASELINES`: past papers have no value for them, so they are not compared; see "Comparison measurements" below. #318 called this kind `placeholder` and said every paper gets 0.5, which is wrong for the scored paper whenever the context pipeline runs). Each compared entry shows each past paper's value, the range, the average, the signed difference, the weighted size and whether the paper is outside every past paper's range; a `not_compared` entry has none of these (null), shows this paper's value only when it is the engine's own, says "not compared: past papers have no value for this", and is listed after every compared measurement.
13. **Descriptions** live in `original/evidence_features.py`, written from the extractor code (tiers 1–16, `prosodic.py`, `tension_arc.py`), with units for the raw value. Heuristics are called heuristics; where a measurement cannot be put in everyday words (the catastrophe index) the entry says what is computed. A test fails if the table and `ALL_FEATURE_CODES` disagree or any description uses a banned word. The top-5 sections now use these descriptions too.
14. **Rendering.** Markdown: summary, then a table of all measurements, then one section each (this replaces the old "Every countable habit" table when the full list is present). HTML: a table of contents linking to every measurement and one collapsible `<details>` per measurement.

15. **Where.** A new static page in the Original suite, `demo/original/evidence.html` ("Side by side"), built the ADR-012 way (option A: the suite's own HTML, `live.js`, `suite.css` and the `packet.html` / `original-flagged.html` mock card styles; no React, no bundle, so no rebuild). Writing State shows a "See it side by side" button next to "Prepare conversation packet" only when the score response carried `evidence` (an object with `all_features`); otherwise the page looks exactly as before.
16. **Data.** Nothing new is computed in the browser and nothing is re-scored. Writing State already keeps the last analysis in `sessionStorage['original_last_result']` (cleared on sign-out); when present it now also keeps `result.evidence` and `result.preliminary`. The API adds `evidence.baseline_papers`: for each "past paper N", the stored `assignment`, `submitted_at`, `provenance` and `word_count` of that sample (only what is stored; `null` otherwise).
17. **Sections.** (a) a summary from the full list's own flags: "outside the past-paper range on N of M active measurements, within on K" (M = `located` + `whole_text`; N = `outside_past_range`), a by-group table using the suite's plain tier names, and the reminder that a range of P past papers is just their lowest and highest value; (b) "Biggest differences": the engine's top list in its order, as side-by-side cards; (c) "Where it held steady": active measurements inside the range, smallest |difference| first, up to 3 with sentences on both sides and then up to 2 whole-text ones (the rule is printed on the page); (d) "Every measurement": one keyboard-operable `<details>` per listed measurement in the #318 order, with each paper's plain and 0–1 values, and for the located ones the two-column quotes; the measurements on which every paper has the same fixed value, and the `not_compared` comparison measurements, are collapsed into "Not used in this comparison" with the reason (and the value where there is one); (e) the past papers table (title, date, how it was added, length, only the columns that have data).

Marks are drawn only when the passage slice at the API's offsets equals the API's `match` exactly. Unit tests: `demo/bluebook/unit/evidence-view.test.mjs`.
19. **Notices.** The mock's "starting point, not a verdict" box is kept, in the suite's wording, with the suite's testing notice under it. The preliminary chip shows the server's own label ("Preliminary · unvalidated · not a judgment") and band words, only when `PRELIMINARY_SCORE_ENABLED=1` sent it. Thin baselines (below the readiness minimum) carry the suite's "treat this as inconclusive" line; no past papers with text shows an explicit empty state.
20. **Who sees it.** Staff and teachers only: `Live.gate` sends a student session to Collections, and the server never attaches `evidence` or `preliminary` for a student principal or `/me/work`. 21. **Tests.** Static contract tests (`tests/test_original_suite_static.py`), unit tests for the templates and the banned-word check, and `demo/bluebook/e2e/teacher-evidence.spec.mjs`: flag off in the main e2e run; `@evidence-on` against a second CI server started with both flags on (cards render, every mark equals the API slice, every measurement is listed, the 7 comparison measurements are under "Not used" and never in the top list, axe WCAG 2 A/AA passes on the page, a student never sees it).

## Comparison measurements: not compared until past papers have values (fixed on `fix/comparison-placeholders`)

**What was wrong.** `extract_features` makes every stored past-paper vector (baseline upload, imports, admin seeding, the stores' rebuilds) and computes no comparison measurement: it writes a 0.5 stand-in for the 7 comparison codes. Only `compute_full_features` fills them, and only for the paper being scored, against its past papers; the score route runs it when the context pipeline is on (`CONTEXT_MANIFEST_ENABLED=1` or `ADAPTIVE_WEIGHTS_ENABLED=1`; `run.py --demo` sets both, the pilot's `render.yaml` sets both to 0). So with the pipeline on, the scored paper had a real value and every past paper the stand-in. Two of the codes (`punctuation_error_ratio`, `error_kl_divergence`) mean "close to the baseline" when high, so in the Chesterton-vs-Mill fixture they were the engine's top two "differences" (1.0 and 0.955 against 0.5). #318 described all 7 as "0.5 for every paper"; that was wrong for the scored paper.

**Decision (Andrew, 2026-10-25: "Fix the placeholders").** Leave them out of the comparison until past papers get real values.

- *Detection is by the computing path, not by value.* `features/baseline_scope.py` holds `NOT_COMPUTED_FOR_BASELINES` (the 7 codes) and its mask; `extract_features` writes its stand-ins from that same list, so the list is the computing path's own record. No code compares a value with 0.5 to decide this.
- *Score.* `StudentState.active_feature_mask` drops them for every baseline size, including the one-sample cold start that used to keep every dimension active. `score()` puts the past-paper mean in their place before anything else, so z is 0 there and the unit vector, the Born probability and the trajectory alignment see the paper as if no comparison value existed. `feature_vector` in the response still reports the measured values.
- *Lists.* `_decompose` leaves them out of the destructive and constructive lists, the entanglement pairs and `tier_breakdown` (tiers 0 and 11 disappear from it, since all their codes are comparison codes).
- *Consequence.* The T1-T11 "vocabulary-spike + error-vanish" pair and the `ghostwriting_confirmed` escalate override in `_recommend` read `error_kl_divergence` / `stumble_rate_consistency` from those lists, so neither can fire now. Both were comparing a real value with the stand-in, so they were not measuring what they claimed; they come back when past papers have real values.
- *Evidence.* Kind `not_compared` (was `placeholder`), described as computed for the scored paper but not for its past papers; past values, average, range, difference, size and outside-range are null; listed last; never in the top list, never in the page's counts. The side-by-side page puts them under "Not used in this comparison" with "Not compared: past papers have no value for this." (it used to list them with a one-sided note).
- *Unchanged.* NORM_BOUNDS, constants and the feature order. With the context pipeline off (the pilot) the scored paper also holds the stand-in, and for 2+ past papers the old value-based check already dropped these dimensions from rms_z, so deviation and action do not move; only the lists and `tier_breakdown` change. Measured impact: `docs/calibration/comparison_not_compared_2026-10-25.md`.

**Option not taken: leave-one-out values for past papers.** Each past paper could get its own comparison values by running `compute_full_features(paper_i, other past papers)`. It is honest in principle, but not trivial: it needs every stored vector recomputed (and recomputed again whenever a past paper is added or removed, because each value depends on the others), it is undefined for one past paper and weak for two, a value against N-1 papers is not like-for-like with the scored paper's value against N, it costs N extra comparison runs per change, and the 7 dimensions would then need fresh calibration before they move scores. Exclusion is the safe default until that work is approved.

## Finding (not fixed here; changes scores, needs Andrew)

`features/preprocess._DOUBLE_QUOTE_BLOCK` (`"[^"]{200,}"`) is meant to drop long block quotes but matches from one short quotation's closing mark to the next one's opening mark. Any paper with two short quotes more than 200 characters apart loses all the prose between them from measurement (demo: 121 words -> 7 measured; the Chesterton fixture: 125 of 1,441 words measured). This likely affects alpha calibration. The evidence layer now exposes it ("What Original measured"), but the fix belongs in a separate, approved, re-calibrated change.
