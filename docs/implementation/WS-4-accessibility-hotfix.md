# WS-4 — Accessibility: exam-flow hotfix, then AA

> Part of the [Master Implementation Plan](../AUDIT_2026-07-06.md) (Audit §9). Refs are a 2026-07-07 snapshot — resolve each cited `path:line` by its **named symbol** via [ANCHORS.md](ANCHORS.md); the tree is under active edit and line numbers drift.
> **Findings:** W1–W6, W12, W13, W14 (NOW, in the existing HTML/JSX) · **Effort:** 2–3 days · **Depends on:** — · **Unblocks:** the pilot's legal exposure on the locked-down exam flow (a blind candidate can currently neither name the answer field nor hear a proctoring warning recorded against them); gives WS-8 a passing axe baseline to preserve through the React rebuild.

## Objective
Make the two legally riskiest flows — student login→dashboard and the Bluebook proctored exam→seal — operable and perceivable without a mouse or sight, **in the existing vanilla-HTML and JSX code**, without waiting for the WS-8 React migration. "Done" means: every click target is keyboard-operable, the exam textarea and all Bluebook inputs have accessible names, proctoring warnings / login errors / timer milestones are announced to a screen reader (and warnings persist instead of vanishing after 5 s), and a contrast token sweep clears the worst 1.4.3 failures. Acceptance is an axe scan of `student.html`, `professor.html`, and the Exam flow at **zero critical/serious** plus a completed keyboard-only login→exam→seal walkthrough. The durable structural fixes (headings, SPA focus/title, chart alt text, reduced-motion, skip links, extended-time UI) are **deferred to WS-8** — see the deferred note below.

## Risks & watch-outs
- **Bundle drift.** Every JSX edit (4.1, 4.2, 4.3, 4.6) is inert in production until `npm run build` regenerates `bluebook.bundle.js` and it is committed. Batch the JSX edits, rebuild **once** at the end, commit the bundle in the same PR. Forgetting this ships a green-looking diff that changes nothing live.
- **Removing the 5 s warning auto-dismiss (4.2) changes proctoring UX**, not just a11y — the banner now stays until dismissed and warnings accumulate in a list. Keep the existing 1.5 s duplicate-collapse (`lastWarnRef`, `Exam.jsx:331`) so a single tab-switch still records one notice, not two.
- **`role="alert"` is assertive and interrupts** — use it only for the recorded-warning banner and login errors. Route timer milestones and autosave through `role="status"` (polite); an assertive timer would talk over the candidate every minute.
- **`student.html` is uncommitted (`M`).** Layer these edits on the working copy, not on `HEAD`; confirm the existing local diff is intentional first so this workstream doesn't silently absorb or revert it.
- **Contrast sweep touches shared tokens.** Raising ink-alpha and darkening `--text-muted` affects every page that reads those variables, not just student/professor — spot-check operator/playground/lab/coach after the change so nothing regresses (e.g. a token used for an intentionally-faint decorative rule).
- **Scope discipline.** Do **not** add headings, SPA focus management, chart alt text, skip links, reduced-motion, or extended-time UI here — they are WS-8 (see deferred note). Adding them now duplicates work the React rebuild redoes properly.
